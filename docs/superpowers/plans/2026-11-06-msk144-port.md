# MSK144 in UberSDR's jt9 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `jt9 --msk144` (and `-k`) in UberSDR's jt9, byte for byte with WSJT-X 3.2.0-rc1's jt9 on every test case, plus MSK40 short messages and SWL mode behind flags that default off.

**Architecture:** A line-for-line C++ port of WSJT-X's MSK144 Fortran (`decode_msk144`, `mskrtd` and the routines beneath them), in new `src/msk*` files compiled with the FT8 floating-point contract, dispatched from `src/jt9_cli.cpp` as mode 144.  Each piece is proved against a small Fortran oracle built from the reference's own routines before the next piece lands; the whole decoder is proved with `scripts/jt9-compare.sh` against the reference jt9.

**Tech Stack:** C++17, CMake, FFTW3 (single precision), gfortran oracles, podman (Docker-compatible) for the `wsjtx-oracle` image, bash check scripts.

**Spec:** `docs/superpowers/specs/2026-11-04-msk144-port-design.md` (read §3 Goals/anti-goals, §6 command line, §7 parity, §8 order).  Repo map (paths and line numbers as of eab0941): the house method lives in `CMakeLists.txt`, `build.sh`, `scripts/fst4w-oracle.sh`, `scripts/jt9-compare.sh`, `scripts/jt9-wine-check.sh`, `src/jt9_cli.cpp`, `src/ft4_jt9.{h,cpp}`.

## Global Constraints

- Reference: WSJT-X **3.2.0-rc1, commit 567ad29ce**, cloned to `~/repos/wsjtx` (the path `scripts/fst4w-oracle.sh` defaults to).  3.0.2 (ccdfaf3c1, `/opt/git/sigmond/wsjtx`) is the A/B only.
- Parity: for the same files and command line, the same stdout, stderr, exit status and every file left in the data directory, on x86-64 Linux; on arm64, every printed line.
- Arithmetic: every new MSK file compiled with `${FT8_FP_OPTIONS}` (`-ffp-contract=off`, plus `-mno-fma` on GCC < 13); maths from `src/ft8_maths.h` wherever gfortran's code calls libm (add any missing function there, ported from glibc 2.39, never the platform's).
- Fortran ported line for line, so the two read side by side; each C++ function names the Fortran routine and its line range in a comment.
- MSK144 writes nothing to `decoded.txt`; decodes go to stdout.
- The last mode on the command line wins (`-Y --msk144` decodes MSK144).
- `mskrtd`'s saved state resets at the start of every file, `--feed` included.
- New flags `--msk-shmsg` (MSK40, WSJT-X `bshmsg`) and `--msk-swl` (WSJT-X `bswl`), both off by default.
- No change to what FT8, FT4, FT2, FST4W or wsprd produce: `./build.sh --check` passes after every task.
- Non-goals: `jt9 -s` for MSK144, WebAssembly, training (`btrain`) and `pcoeffs` (fixed off and zero, as file mode has them).
- Credits and GPL v3 notice carried into every new file's header, as the existing ports do.

## Review Focus

1. A 30 s WAV given with `-p 15`, and a WAV shorter than one period: same lines and status as the reference (Task 7 cases `odd-*`).
2. Several files in one process (`jt9 -k a.wav b.wav` and `--feed`), where the same message repeats across files: the repeat prints in both files, as in the reference's one-process-per-file run (Task 6 test `msk144-repeat-across-files`).
3. Silence, pure noise and a clipped WAV: no decode at all, since a false decode fails parity (Task 1 cases; checked in Task 6).
4. `-Y --msk144` and `--msk144 -8`: the last mode wins in both orders (Task 6).
5. `-F` beyond the tolerance the reference allows, and `-f` at the band edge: same clamping as `jt9.f90` (Task 6).
